### A. Co-Review, folded into #3, #1, #2, #11, and the shipped HTML page

- **What.** Open source, MIT, an Eclipse Theia app, with a Claude Code plugin and native packages for Pi and Oh My Pi. Other agents use the MCP server. [repo](https://github.com/sdsvn/co-review). [site](https://sdsvn.github.io/co-review/).
- **Audit.** `/co-review:audit` writes the overview as a guide in four chapters: lay of the land; how it works; patterns, naming, and why; where it hurts. Every claim links to the code. What the agent could not verify is marked inferred or unknown, and an unknown "why" is asked rather than invented. The guide's first line names the commit. Each chapter ends with one check question. The workflows page calls it a Check, a prediction such as where a new command would go. The reader selects it and comments an answer. The agent contract says those comments come back on the overview, with the quoted text, which is how check answers arrive. [workflows](https://sdsvn.github.io/co-review/docs/guides/workflows/). [agent contract](https://sdsvn.github.io/co-review/docs/reference/agent-contract/).
- **Goal, from the workflows page.** Afterwards you can, without the agent, say where things live, use the repository's vocabulary, trace its main flows, recognise its patterns and naming, follow its house rules, know where it is fragile, and place a change and predict what it affects.
- **Coverage.** `get_review` returns `coverage`: files the reviewer marked viewed, overall and per area, and `next`, the area's first file not viewed yet. A file changed since it was marked viewed counts as not viewed. That is a reading signal. It is not a quiz score.

Graphify's own star count and posts stay on open PR #13. They are not copied here.

### D. CodeLens, folded into #7, #8, and #17

- **What, from the README.** npm `@blong8334/codelens`. A pull request or a local branch opens as a brief: what the change does and why, risks, and where to start reading. The review queue then takes one change at a time. Each step shows that change's diff, who calls it (callers outside the change marked), which routes, CLIs, and jobs reach it, and which databases and APIs it touches. The model writes the explanations. The checks come from the call graph. Tree-sitter parses 15 languages: TypeScript, TSX, JavaScript, Python, Java, Kotlin, Scala, C#, Go, Rust, C, C++, Swift, Ruby, and PHP. TypeScript and JavaScript also get types from the TypeScript compiler. Other languages resolve calls by name. Dynamic dispatch can be missed, and those edges are dotted as inferred or omitted. [repo](https://github.com/blong8334/codeLens).
- **Cache.** A SQLite or Postgres store keyed by content. The README says re-reviewing after a push only pays for what changed. Parses and descriptions are cached. The per-change risk pass is not cached yet. A function's "why" is cached with its own source, so it can go stale when only its callers change. The explore page lists what is new or changed since the last look. The snapshot's commit id is what that phrase refers to.
- **Package.** npm created 2026-11-07T01:06:26.178Z. Version 0.1.2 is `latest`, published 2026-11-11T12:47:26.325Z. License Apache-2.0. GitHub API at 2026-11-11T13:20:30Z: `stargazers_count` 1, `forks_count` 0, created 2026-11-03T13:04:00Z, Apache-2.0.

### E. SAFE, folded into #9 and #11

- **Paper.** "Code-Grounded Agentic Explanations for Static Analysis Vulnerability Findings," Johnson, Krishnamurthy, Shanmuganathan, Piskachev, and Bodden. arXiv 2611.13041v1, published 2026-11-09T11:40:08Z. SAFE is an IntelliJ plugin. Detection stays with a SAST tool that reports SARIF. The model only explains. Explanations are tiered by demand: a one-sentence summary, then what, why, where, and how to fix, with an opt-in deep dive. Each explanation is tied to the reported data flow. The agent must consult the repository and the rule that fired before answering. The predecessor (SAFE-Blue) used one prompt and a beginner, intermediate, or advanced selector. SAFE-Red is the redesign. The HTML was read in this session. The numbers below are from the abstract and from section 4.4.
- **Study.** Within-subjects crossover, 24 participants, both builds, security findings. The paper calls it a controlled within-subjects experiment. People were not split into a tool group and a control group. It is not tagged `measured-RCT`. The two builds differ in the interface and in the agent at once, so a difference is not isolated to the tier or to the grounding. Twelve of the 24 reported less than a year of Java. Fourteen had never used a SAST tool.
- **Usability.** System Usability Scale 85.0 for SAFE-Red against 77.3 for SAFE-Blue (z=-2.55, p=.011). Seventeen of the twenty-two non-tied participants rated SAFE-Red higher.
- **Remediation.** Correct proposals: 19 percent with SAFE-Blue, 41 percent with SAFE-Red. The results section's odds of a better-quality proposal are 2.6 (95 percent CI 0.93 to 7.09, p=.069). Adding period and finding set raises the estimate to 2.8 (p=.064). The abstract prints "the odds of a correct remediation were 2.6 times higher."
- **Nulls.** Triage accuracy 0.46 against 0.53 (Wilcoxon p=.59). The paper says the tools are indistinguishable and reads that null as uninformative rather than as equivalence. Time per finding: per-participant medians 5.1 minutes against 4.7 (p=.21), also called indistinguishable. Trust in the assessment moved +0.04 and is described as effectively unchanged. After Holm correction across the five perception items, no individual comparison remains significant. Actionability's raw gap is +0.67 (raw p=.011, Holm p=.057).
- **Interviews.** The abstract says grounding made findings easier to understand rather than easier to believe. Section 4.4.4 says grounding appears to support locating and understanding a finding rather than believing a verdict. Two participants separated those two ideas. Section 5 says grounding appears to serve comprehension rather than belief.
- **Evidence.** A within-subjects measurement on security findings. Not `measured-RCT`.
- **Decision.** #9 gets the on-demand tier (summary open, deep dive on request). It is not a familiarity split from git history. The predecessor's audience selector is the other design, and the study does not separate it from the agent. Quiz score stays the guard. #11 gets the rule that the agent must read the repo and the fired rule, the data-flow tie, and the result that grounding did not move trust. No new row. The rank of #9 and #11 stays.

Review quality only. The guide, the check question, the coverage, the tour, the ask, the callers, and the explanation tiers stay in the sections above.

Optional post of that review to GitHub through `gh`. [workflows](https://sdsvn.github.io/co-review/docs/guides/workflows/).
