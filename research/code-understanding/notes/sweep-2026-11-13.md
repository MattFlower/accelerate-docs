### B. code-walkthrough — #6, #7, #8, and the HTML page

- **What, from the README.** A Claude Code plugin. Other harnesses are untested. It renders a pull
  request, a diff, or a code area as a page read top down. The overview is two sentences and a few
  bullets, with no file names. Files sit in three to five themes, with one picture per theme drawn
  from real names in the diff. Then a call graph, then a one-line role per file and a note per
  hunk. Inside a theme, callers come before callees. Select text and Ask. The answer can add or
  replace a block. Undo removes it. The edit is local. "Hand to my session" passes a task to the
  reader's own Claude Code session. "Copy gh command" prints the calls that post review comments.
  Nothing is posted unless the reader does that from the page. The page is a local file.
  [README](https://github.com/crisperity/code-walkthrough).

### C. Atoms of confusion — one line each on #1, #4, and #11

- **Paper.** "Does Confusing Code Confuse LLMs? A Pilot Study on C++." Tim van de Wetering, Lola
  Solovyeva, Fernando Castor. arXiv 2611.15575v1. The API `published` and `updated` values are both
  2026-11-11T14:59:11Z. [abs](https://arxiv.org/abs/2611.15575). The HTML results section was read
  in this session.
- **Setup, from the methods.** C++ from ImGui, Boost.QVM, and ranges-v3. ChatGPT is GPT-5.3.
  GitHub Copilot is Claude Haiku 4.5. Output prediction also uses Gemini Flash 3.5. Explanation
  uses 20 samples per atom. Output prediction uses 5.
- **Results, from section 4.** Code-explanation accuracy stayed at 100% across nearly all atoms.
  The plot is omitted in the paper. The exception is ChangeOfLiteralEncoding, at 90% when the atom
  is present, from reading octal literals as decimal. Output prediction fell for that atom
  (ChatGPT from 5 to 2, Copilot from 5 to 4), for omitted curly braces (both from 5 to 4), and for
  SFINAE versus concepts (ChatGPT from 4 to 2). The paper names atoms with no drop, including the
  comma operator, infix precedence, and pre/post increment. The authors write that generating
  high-level explanations may rely more on retrieving learned representations than on simulating
  execution.
- **Evidence:** `measured-obs` (pilot, small).
- **Our own idea.** A fluent explanation is weak evidence the model traced the code. #1 should
  include at least one output-prediction question, checked against the code or a run. #4's worked
  example should include one too. The captured command already on #4 is the check. #11 treats a
  confident explanation as weak evidence that a claim is grounded. One line on each item. Rank
  unchanged.
