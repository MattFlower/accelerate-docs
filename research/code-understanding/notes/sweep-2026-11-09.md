## Findings

### A. Cognitive Tours, folded into #3 and #5

- **What, from the HTML paper and the arXiv API.** Margaret-Anne Storey, University of Victoria. arXiv 2611.08456v1, published 2026-11-05T18:48:06Z. The arXiv comment is "6 pages, shorter version submitted to ICSE 2027 Demo Track (under review)." The abstract's demo URL is https://cognitive-tours-demo.vercel.app/. A GET on 2026-11-09 returned HTTP 200 and a Next.js page. A reader fetch of the same URL showed "Loading…". The tour UI was not clicked. The paper says a visitor can open the tour "A Research Story Behind Cognitive Tours."
- **Waypoints.** A waypoint is a landmark the author chooses: a goal, a user need, a feature, a design decision or ADR, an AI instruction, code, a test, a risk, or an open question. A tour is an ordered subset, with docent notes between stops. Tours can be exported as markdown. Links open the artifact on GitHub or in the IDE.
- **Skills.** Four Claude Code skills, run in the repo. They read the live map, git history since a date, and the linked files. They do not write the map. `audit-waypoints` flags a description that no longer matches its file. `audit-tours` flags unrecorded recent work and a stale tour narrative. `suggest-waypoint` ranks recent work worth recording and then asks the author to explain it. `suggest-tour` proposes where new waypoints fit and asks the author to write each bridge. A draft is written only on request, after the author has been asked to write their own text. Figure 3 shows `/suggest-waypoint since 2026-10-20` ranking a decision that contradicts ADR 007 (still Accepted) first, then asking "What was decided, in your words?"
- **Evidence.** The contribution is "a tool and interaction design proposition, not a validated claim (yet)." The author reports her own use across six months, and one evening of more than 20 commits where the skill surfaced an ADR the map still treated as accepted. The proposed evaluation, including whether writing a tour changes the author's own understanding, is future work. Evidence: `practitioner`. The author built the tool, so the report is also vendor-ish. It is not a measured study.
- **Table I, as printed.** Rows: Spec Kit and Kiro; Lattice; SpecStory; CodeTour; LACY; as-built architecture; Diagnostic Legibility; DeepWiki and Code Wiki; Bram (https://github.com/judell/bram, HTTP 200 on 2026-11-09); Cognitive Tours. The prose, not the table, also names CodeMap. The paper cites Learning Opportunities, /grill-me (https://www.aihero.dev/skills-grill-me, HTTP 200), and the Feature Comprehension Score (https://feature-comprehension-score.elliedocs.com/, HTTP 200) as questioning or reflection tools whose main deliverable is not a persistent account of the software. Those three URLs were opened. Their page text was not used as a source. Learning Opportunities is already on #1 and #3.
- **Decision.** No new ranked row. The human-written tour is a source on #3, next to LACY and CodeMap. The capture rule is on #5: after a session, rank the decisions in the diff, flag one that contradicts an ADR or the rules file (#10), and ask the human to explain it in their own words. The model may list facts. The stored why is the author's. That rule is `our own idea`, adapted from `suggest-waypoint`. The test added on #5 is one real limitless or accelerate session diff: does the author's explanation name a mismatch, and does a second reader's quiz differ with the entry and without it. ### B. LACY and CodeMap, one source each on #3

- **LACY.** [arXiv 2603.25391](https://arxiv.org/abs/2603.25391), FSE 2026 companion (industry). Expert-curated code tours, comprehension questions, and an AI-only exploratory tour. Within-subjects. Seven Beko participants: two domain experts and five learners, on one legacy VB.NET finance codebase (30K+ lines). Guided-tour quiz 83%, AI-only tour quiz 57%. Expert ratings of verbal explanations were 79% and 76.8%. The paper says guided tours took about 25 minutes and AI-only tours about 35. There was no documentation baseline, because the codebase had none. The backlog line uses the quiz and the sample of five. Evidence: `measured-RCT` (small, one system).
- **CodeMap.** [arXiv 2504.04553](https://arxiv.org/abs/2504.04553), accepted at ICPC 2026. Hierarchical maps (global, local) for an unfamiliar codebase. User study: nine experienced developers and six novices. The paper states 79% less time reading model replies than ChatGPT (1.15 vs 5.48 minutes). Those two minutes are 79%. The same sentence prints t=1.47, p=.008. This pass did not recompute that test. Map time versus the static tool Understand was 8.55 vs 4.50 minutes (90%, t=3.67, p=.011). Time reading code in the editor was 2.08 vs 8.18 minutes (the paper's 75%, t=-7.87, p=.0002). The sections read report perceived usefulness and time. They do not report a comprehension quiz. The backlog cites the 79% and the 90%. It does not label this a randomized trial.

### E. Tracybot, folded into #5 and #6

- **What.** arXiv 2611.09395v1, published 2026-11-06T12:34:02Z. Seven authors, led on the page by Răzvan Albu. A Tasklet is the build prompt, up to five earlier prompts in the same session that changed no files, the agent's replies, and the resulting edits. OpenCode separates plan and build with its own modes and is read through its SDK. Claude Code and Codex use hooks, and the cap of five is the fallback where there is no plan mode. Snapshots are hidden commits under `refs/tracy-local/*` and, after commit, `refs/tracy`. A git note links the commit. AI Blame is a separate read-only tab. Export is a MADR record. The developer writes the reasons and the consequences. The paper's Table I compares Git AI and Cursor Blame (the unit is the whole session, and the user sees a summary) and PromptTrace (the unit is one prompt).
- **Study.** Focus group after a demonstration: five practitioners and two students. Survey of 24 people judging screenshots of five scenarios. 19 had at most two years of professional experience, four had 3–5 years, one had more than five. On a six-point scale, 17 of 24 rated the interface 4 or higher, and 21 of 24 rated the Tasklet a clear representation of intent. In four of the five scenarios, more than 83% agreed with the attribution shown. The similarity threshold in the tool is BLEU 0.75. The paper says participants did not use the tool. Future work names a comprehension comparison that has not been run.
- **Stars.** GitHub API, call issued after the clock read 2026-11-09T13:23:42Z: `stargazers_count` 10, `forks_count` 0, `license.spdx_id` GPL-3.0, created 2026-03-25T09:38:28Z, default branch `main`. [repo](https://github.com/TracyTeam/tracybot).
- **Decision.** On #5, the Tasklet is the unit stored for an agent-written line, and the MADR export is the same decision-record idea with the human writing the judgment sections. On #6, a click on a line returns that Tasklet, not the whole session and not one short prompt. Evidence: `vendor`. The study is usability. It is not a comprehension result. The star count does not move #5 or #6.

### F. Structured code reveal, one caution on #8

- **What.** [arXiv 2609.24616](https://arxiv.org/abs/2609.24616). Submitted 2026-09-21. Latest version v2, 2026-10-29. The title on the HTML is "Structure-Aware Rendering: How Code Reveal Shapes Programmers' Visual Attention." Within-subjects, Latin square, three Java snippets, 34 seconds of viewing, then a retention quiz and a comprehension quiz. 53 participants recruited. Gaze analysis excluded nine, leaving 44. Structured reveal shows syntactic structure before the details inside it.
- **Results used.** Versus character-by-character reveal, structured reveal had a lower fixation rate (p<.01), longer fixation durations (p<.01), and more variable fixation durations (p<.001). Table 4, N=44, mean comprehension: static 4.886, structured 5.000, character 4.932. Mean retention: static 4.659, structured 4.364, character 4.432. The prose says performance was similar across the dynamic conditions.
- **Earlier notes.** This arXiv id is not in the code-understanding notes or backlog on this branch. Other eye-tracking studies are in `research/making-prs-easier-to-review/`. They are not this paper.
- **Decision.** One caution on #8. The study is about how a short snippet appears. It is not a result about call-graph order on a pull request. The quiz scores sit together, so the item stays where the perspica evidence put it. Evidence: `measured-RCT` (lab snippets).
