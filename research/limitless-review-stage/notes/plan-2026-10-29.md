# Review stage: plan to gain ≥10 points of blocking recall (draft 1, 2026-10-29)

Evidence: reports/Code review recall improvement.md (deep research + internal analyses), NOTES.md.
Target: **+10 absolute points of grounded blocking recall** on a frozen, pooled and adjudicated gold
set, scored by a validated semantic matcher, with clean blocks within a pre-registered margin.
(A relative 10% would be 3.4 points, inside run-to-run noise.)

## Why "nothing adopted" so far is partly the ruler
- The ±5-line grader is noisy in both directions (~20% of its credits were a different defect nearby; ~4% of
  its misses were the same defect elsewhere). FINAL judged dev recall (Phase 0, phase0/RESULTS.md: two-judge
  consensus + code-reading tiebreak): production 31.6%, sol@high 41.8% (+10.2), adversarial 49.0% (+17.4),
  union-of-2 D 47.4% (+15.8), checklist F +14.6 on its cohort; held-out production 18.6%, adversarial 25.6%, D 33.0%.
- Clean guardrail = 8 dev trials (95% upper bound on a block-rate rise: 37.5%); a third of past
  "clean" cases had real defects; D was rejected on 3/26 (CI 2–30%).
- Power: +10 at 80% needs ~160–200 gold defects at k=2 (~110–130 at k=4); dev has 49.
- Same-system runs differ 8–10 points, ~2× trial noise → run-level drift; the +8 rule accepts a
  null variant 16–21% of the time and misses a real +10 ~40% of the time.
- The only same-run paired comparison (E1): sol@high vs sol@medium 41/98 vs 31/98 = +10.2 (3/8 vs 2/8 clean).
  Earlier figures in this file and the report (+7.1, +9.2, 42.9%, 44.3%) came from partial audits; RESULTS.md supersedes them.
- Held-out "clean" review-068/092/108 contain real medium defects (both vendors, reproduced; 068's later fixed by #647).

## Reviewer weak points (production data since 10-07)
- Sol stops early: 0.57 findings/review in production (eval 1.1), ~2 of 20 minutes.
- Opus finds but under-rates: 15% blocking recall vs 30% at any severity; Sol ∪ Opus(any) 50% vs Sol 34% (hypothesis).
- 6.4% of orchestrator escapes were already reported by the factory as minor/nit or parked as a later-round follow-up.
- Escapes per PR unchanged by the Opus→Sol switch (~1.9 round-1 blocker/major per PR): procedure, not model.
- The gold comes from a *procedure*: a PR-specific brief (checkable claims, every caller, inputs,
  targeted questions) → Sol@high with write access for regression tests → mutation check.

## Phase 0 — free, on stored trials (1–2 days, no paid runs)
0a. Semantic matcher: two LLM judges from different families (report their disagreement per arm),
    location as a prefilter, one-to-one assignment, no double credit; validate on the 358 already-judged
    pairs (grader_verdicts.json + credited_verdicts.json) + ~50 hand checks. Keep the ±5 score alongside.
    Re-score every stored review eval. → corrected baselines.
0b. Blind two-vendor adjudication of every clean-case block in stored trials (incl. D's 10/26); relabel.
0c. Replays: two-tier blocking rule on D's stored findings; Sol ∪ Opus with deterministic severity;
    judge-check the 12 Opus-only defects.
Deliverable: a corrected history table (which past variants would have passed).

## Phase 1 — fix the instrument (~1 week of factory + orchestrator time)
1.0 **Gold completion by pooling (Matt 10-29: the existing gold was never independently reviewed, so
    past improvements found real defects that earned nothing).** Applies to the existing 135 cases AND
    every new case before any arm is scored:
    - Pool every blocking finding any system ever reported on the case (all stored eval trials: E1, E2,
      E3, probe, D, trace, checklist, opus@high; e.g. the 158 "DIFFERENT" near-misses) plus fresh deep
      sweeps by several diverse strong reviewers (oracle-style brief + Sol@high, Opus@high, adversarial
      Sol, attack pass on trust-boundary cases, plus the cheap models Haiku 5.5 / Luna 6 / Terra 6.1), k≥2 each — paid once, per case.
    - Adjudicate each pooled finding blind (system identity hidden): two vendors, reproduction where
      possible, orchestrator confirms disagreements; real ≥ medium → gold, else rejected (recorded, so
      later arms reporting it are counted as known false positives, not unjudged).
    - Clean cases get the same sweep; a real defect relabels the case.
    - Ongoing (TREC-style): when a tournament arm reports a finding not yet judged, it is adjudicated
      blind before the decision, then frozen into the gold for every arm. No arm is scored against
      unjudged findings, so finding new real defects counts.
    - Report "recall vs pooled gold" as the headline and "recall vs original gold" alongside.
1a. Escape corpus: run #833's generator over the 209 orchestrator rounds (136 PRs) → two-vendor
    proposed labels → orchestrator confirmation (LABELS.md process) → expect ~200 gold defects.
1b. Clean set: merged factory PRs with no later finding, purged by linked-fix/SZZ search and audited
    blind by two vendors → ≥60 clean PRs.
1c. Independent gold (not from the oracle): fix PRs/commits that name the PR that introduced the bug;
    replay the introducing PR at its base. Needed to judge option A fairly.
1d. Splits: random by PR within each reviewer era (escapes are selected on the reviewer of the day:
    Opus before 10-23, Sol after), held-out frozen and unseen before any arm runs; record the era per
    case and report arm results per era. Measure the production baseline on new cases with fresh runs.
1e. A/A: production config ×3 runs interleaved in time → variance by defect / PR / run.
1f. New decision rule (pre-registered): paired, PR-clustered bootstrap; adopt if the 95% lower bound
    of the gain > 0 and the point estimate ≥ +10; clean-block non-inferiority margin (Matt picks, e.g. +5 pts)
    on adjudicated clean trials, k≥2 both arms.
1g. Optional external check: GitHub ReviewBench TS/JS slice (~60–80 PRs) via a judge adapter;
    SecBench.js for the security slice.
